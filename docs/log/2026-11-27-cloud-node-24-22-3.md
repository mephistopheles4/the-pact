# The cloud Node pin moves to 24.22.3

**2026-11-27.** PACT-12. Node's November 2026 security release (24.22.3, dated 2026-11-10 in Node's `index.json`) reached the cloud setup's Node pin. ADR 0088 sets a 7-day limit on a security bump, so it was due by 2026-11-17 and is late. It is the third ticket of athanor's spec for testing on Node 26 beside Node 24, which moves the cloud pin along line 24. Sensitive route, as that spec and the lead set it. No spec round of its own: the ticket is cut from that spec.

## What was built

- **`CLOUD_PINS`** in `cloud-sessions/gen.mjs`: `NODE_VERSION` 24.22.3, with its archive and `bin/node` hashes. The mise pins stay as they were.
- **The cloud copies,** `cloud-setup.sh` and `cloud-setup-wrapper.sh`, regenerated: in each, the three pin lines and the marker change, and nothing else.
- **Tests: +0 −0.** Run after the pin edit and before regenerating, `gate/tests/cloud-sessions.test.mjs` failed.

## The pin bump, by ADR 0088

Run in a throwaway `ubuntu:24.04` container, with the image's own `gpgv` (2.4.4) and only the script and a copy of the committed keyring mounted, read-only. The copy's SHA-256 matched the one `cloud-sessions/keys/README.md` records.

- **The release:** 24.22.3 was the newest 24.x in `index.json`, marked as a security release.
- **The signature:** `SHASUMS256.txt.sig` for v24.22.3, checked with `gpgv` against `cloud-sessions/keys/node-release-keys.kbx`: a good signature from `5BE8A3F6C8A5C01D106C0AD820B1A390B168D356`. That key is in the primary releaser keys of nodejs/node's README at commit `c58ccfa61777629023ceb1402b9892158dbe52b1`, and it also signed 24.22.1. The keyring is unchanged. A copy of `SHASUMS256.txt` with one byte changed was refused.
- **The archive:** `node-v24.22.3-linux-x64.tar.gz` hashes to `061ec3e3062115705b56b51fa9cc330ab50d34b6969387d4e4b1a50c6809acc2`, as its line in the checked file says.
- **`bin/node`:** unpacked, it hashes to `a7ec1b37e6ff9d187e4198c5b6df9a4eb1c74dd31804fb3bac55cc4ceca1ac01`, prints `v24.22.3` and bundles npm `11.19.1`.

## The test drivers

`cloud-sessions/test-driver.sh` and `test-driver-wrapper.sh` each ran the regenerated setup in a throwaway `ubuntu:24.04` container, with only a scratch folder mounted, read-only. No credential was passed in.

- **Both passes,** in both drivers, printed `ok: node, npm and npx run Node 24.22.3`. The wrappers ran Node `v24.22.3`, npm and npx `11.19.1`.
- **Pass against pass:** neither driver's snapshot comparison came out empty. Its only changed lines are the file times in the headers of the stale agent comparison below, one per agent file.
- **The Node block's hand checks,** in both drivers: a wrong mise, archive or binary pin each printed its mismatch `WARN` and `INCOMPLETE (… node: hash)`. A missing mise release gave `node: download`, `paranoid` off gave `node: config`, and a `uname` stub printing `aarch64` gave `node: arch`.
- **The Node block alone** took 8 s in one driver and 7 s in the other. An untrusted `mise.toml` asking for Node 22 was refused as untrusted, and the wrapper still printed `v24.22.3`. `mise exec node@22` printed `v22.23.5`.
- **Two stale checks** of the drivers' own, which this change doesn't touch. Each driver exited 1 at its last section, the settings merge's unit tests, which stop at `COMPACT_SCRIPT: unbound variable` and so didn't run: the lines the driver lifts from the setup don't define it. And the agent comparison reports each of the nine agent files as differing: the only difference is the `model:` line, which the cloud copy writes as a model name where the source names a role.
