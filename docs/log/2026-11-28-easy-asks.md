# Easy asks

PACT-71. The owner wanted easy, low-risk asks to go ahead without a separate yes, as checkpoints the owner reviews after. The rules file already kept no stop of its own; the wait came from a lead in the head chef's Auto mode, which holds each checkpoint. [Spec 0012](../spec/0012-easy-asks.md) says what is built.

The rules file gains an **Easy asks** bullet after Checkpoints, outside every part: a closed list of two asks, an edit to the pact configuration that turns on an opt-in tool that sends, fetches and posts nothing and holds no identity, and rebuilding the Scriptorium page with the installed Scriptorium kit. The session runs the dry run or check itself first and puts its output in the record. No one holds an easy ask, a lead in Auto mode included. An install's apply, `mise trust`, a loosened control, a written secret, a change of identity and anything that sends off the machine are never easy.

The first draft named easy asks by three open tests. The spec round found that those tests let a session switch off a guard, open a send to TypeSafe or trust a clone's mise config, so the list became closed and the exclusions explicit. The install's apply stays the owner's word in chat, as the issue's third done-when said; that is the session's pick, open for the owner as decision D1. Aligning the head chef skill's own Auto-mode text is a note for grimoire.

The threat model's "Rules it rests on" paragraph names the easy-asks rule; no class text changes.

**Deploy:** install from one dry run, on the owner's go-ahead, and paste the cloud wrapper into the cloud environment again. Then, in the first lead session at Auto, check that an easy ask goes ahead with no waiting entry.

**Rolling back:** revert the merge commit, then dry run and apply; on drift or the behind warning, stop and ask.
