# Easy asks

PACT-71. The owner wanted easy, low-risk asks to go ahead without a separate yes, as checkpoints the owner reviews after. The rules file already kept no stop of its own; the wait came from a lead in the head chef's Auto mode, which holds each checkpoint. [Spec 0014](../spec/0014-easy-asks.md) says what is built.

The rules file gains an **Easy asks** bullet after Checkpoints, outside every part: a closed list of two asks, an edit that only adds an opt-in tool to the configuration's tools list, for a tool that sends, fetches and posts nothing and holds no identity, and rebuilding the Scriptorium page from the owner's saved file with the installed Scriptorium kit. The session runs the dry run or check itself, never through `npx`, and records its verdict and counts, never its raw output. No one holds an easy ask, a lead in Auto mode included. An install's apply, `mise trust`, a loosened control, a written secret, a change of identity and anything that sends off the machine, now or later, are never easy. Today only the cleaner qualifies as a tool, so in practice the rebuild is what goes ahead.

The first draft named easy asks by three open tests. The spec round found that those tests let a session switch off a guard, open a send to TypeSafe or trust a clone's mise config, so the list became closed and the exclusions explicit. The Test round found that pasting a dry run's raw output into a record can leak repo names and model values, and that an "easy" edit could also switch the coverage tool's backend; the bullet now records verdicts and counts and allows only adding the tool's name. The install's apply stays the owner's word in chat in this repo, as the issue's third done-when said; that is the session's pick, open for the owner as decision D1. "Never easy" adds no wait: outside this repo no installed rule holds an install's apply or `mise trust`, though the threat model says one does, which was true before this change and stays open for the owner. Aligning the head chef skill's own Auto-mode text is a note for grimoire.

The threat model's "Rules it rests on" paragraph names the easy-asks rule; no class text changes.

**Deploy:** install from one dry run, on the owner's go-ahead, and paste the cloud wrapper into the cloud environment again. Then, in the first lead session at Auto, check that an easy ask goes ahead with no waiting entry.

**Rolling back:** revert the merge commit, then dry run and apply; on drift or the behind warning, stop and ask.
