# The clef supervisor: ensure, serve, stop, status and remove

PACT-64, T2 of spec 0002. `claude/tools/clef.mjs` gains the supervisor and five modes. It starts nothing on its own: only `ensure` starts it, and nothing runs at login or boot.

`ensure` takes `run.lock`, starts `clef serve` detached by `process.execPath` with no shell, from `runtime/<tag>/` of the clef folder it checked, and prints one JSON line (`ready`, `starting`, `not-set-up` with exit 3, `failed` with exit 4 inside ten minutes of a failed start). `ensure --wait n` also waits for a supervisor that is already starting. `serve` takes its clef folder from that working folder (it must be `pact-clef/runtime/<tag>`, else it refuses `clef-home`), never from `CLAUDE_CONFIG_DIR`, which the supervisor's named environment does not carry. It binds `127.0.0.1` on a port the OS picks, starts the server on another loopback port from `runtime/<tag>/` with a fixed argument list (the key in `run.key`, `--no-webui`, `--no-slots`, `--cors-origins` with an origin no page has) and a named environment, and answers only `GET /health` and `POST /v1/systemone` to a caller with the token, a `Host` of `127.0.0.1:<port>`, no `Origin`, a JSON content type and a body under 256 KB. It builds the reply itself from checked numbers and choices; the server's own text never reaches a caller (`502 no-answer` otherwise). It stops after 30 minutes with no forwarded request, when the server exits, and when its own script changes or goes (checked before each request and every minute). A live supervisor is one whose `run.json` pid is alive and whose `/health`, asked with the token, returns the same `run`, `pid` and `serverPid`.

The server is spawned non-detached, so on Windows the job object ends it with the supervisor. On Linux it starts through `/usr/bin/setpriv --pdeathsig KILL --`; `ensure`, `stop` and `setup` also end orphan servers under `<clef folder>/runtime/` found through `/proc`, only while holding `run.lock`. The sweep spares a server whose parent is the live supervisor's pid when one is passed in; `ensure` passes none, so its rule is looser than the spec's: a live server of another run under the same folder is also ended. Only one supervisor runs per clef folder, so this changes nothing in use. `setup` now refuses `clef-running` while a supervisor is live and `clef-setpriv` on Linux without `/usr/bin/setpriv`, and holds the lock while it works.

`run.lock` is created exclusive. A lock whose pid is gone is stale and is taken over under a second exclusive step (the folder `run.lock.take`), which re-reads the lock first, so callers that all saw it stale start one supervisor. A start that fails after the server is spawned ends the server, clears the key and records `run.fail` with the word `exit`; a stop leaves a newer run's `run.key` and `run.json` alone.

Builder picks. `remove` runs from the folder above the clef folder, since a working folder cannot be deleted on Windows; it retries the delete for a server that has just ended. A refused request's unread body is read and dropped for two seconds, so a caller sees the refusal and not a reset. On Windows the six names `HOMEDRIVE`, `HOMEPATH`, `LOGONSERVER`, `SYSTEMDRIVE`, `USERDOMAIN` and `USERNAME` reach the server although the list does not name them: Node (libuv) copies them from the caller's own environment when it builds a Windows environment block. The argument `--cors-origins http://127.0.0.1.invalid` is added to the spec's list so that a web page cannot read the server's keyless `/health`. The test seams are parameters of the exported functions: the server program, `pdeathsig`, the timings, the supervisor's script (`scriptUrl`), the supervisor command, the `/proc` root, the kill function and the options `main` passes to `serve`.

Upstream facts, from the llama.cpp b12211 source (`common/arg.cpp`, `ggml/src/ggml-backend-reg.cpp`, `tools/server/server-http.cpp`): `--api-key-file` reads one key per line; `--no-webui` is an alias of `--no-ui`; `--no-slots` turns the slots endpoint off; with a key set only `/health` and `/v1/health` need none, and `/health` answers `{"status":"ok"}`; CORS headers follow `--cors-origins`; with no search path given, backends load only from the compile-time backend folder (if one is set), the executable's folder and the working folder, and `GGML_BACKEND_PATH` is the one environment name that adds a library, which the supervisor never passes.

**Rolling back:** take `clef` off the tools list and apply, then revert the merge. A running supervisor ends itself within a minute, because its script is gone. `clef stop` and `clef remove --yes` free the machine first.
