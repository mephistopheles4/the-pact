# The cloud mise pin moves to 2026.10.14

**2026-11-08.** #477, quick tier, built by pact-477. The weekly advisory watch found GHSA-43hx-4j66-v486 (High, affected `< 2026.10.14`): an untrusted project config could place a repository directory first on PATH through a trust-exempt `path:` tool version. The cloud setup pinned mise `2026.10.2`, so it reached the pin.

## What changed

`CLOUD_PINS` in `cloud-sessions/gen.mjs` now holds `MISE_VERSION` `2026.10.14` and `MISE_SHA256` `5bc573bc…d47f2`; running `gen.mjs` regenerated `cloud-setup.sh` and `cloud-setup-wrapper.sh`. Nothing else moved: the committed minisign key is the one for key id `64113EDF160FDEC2`, unchanged. The security fix overrides the two-week age rule in [ADR 0088](../adr/0088-the-cloud-setup-installs-a-pinned-verified-node.md#the-pin-bump); the release is dated 2026-10-18 (its signed checksum file carries that timestamp), so the 7-day limit was already past when the advisory was published.

## The pin, checked as ADR 0088 says

- **Signature:** the release's `SHASUMS256.txt` checked with `minisign` (Ubuntu 24.04's package, in a throwaway container) against the committed `cloud-sessions/keys/mise-minisign.pub`: "Signature and comment signature verified". A copy with one byte changed failed the check.
- **Hash:** the linux-x64 tarball's hash in the checked file, `5bc573bc…d47f2`, matches the downloaded file.
- **Setup:** the generated Node block, run alone in a clean `ubuntu:24.04` container, installed the new mise and a working `node`, `npm` and `npx` at the Node pin, with no `WARN`.
