# Review comments get diagrams again

#478, standard tier, specified and built by pact-478, led by backlog-lead. The owner's words came relayed by the lead session.

#466's minimal review procedure had cut every diagram rule, so review comments opened on findings with no picture. The owner asked for 1 to 3 diagrams per review comment, reusing the old chart templates, and said the old rules gave a flowchart about 90% of the time. The opening now has a title line, a signal table, the diagrams and a count line, and the Diagrams section brings back the seven-row type table, the pin palette and the centred block, with a flowchart limit: at most one per comment, used only when no other row answers the sentence (ADR 0138).

The spec was posted in three revisions. The owner's two changes on the second were that chat can render Mermaid, so chat gets diagrams too, and that no eval runs for this issue. A trial on three past review comments (#443, #475, #401), run locally, led to three fixes (N counts decisions, not drafted fixes; a quadrant only when the points separate; a fix not yet decided is labelled as proposed) and to the signal table coming back on the owner's word; its colour rule waits on the owner. No lens ran on the spec, on the owner's word; the security pair at Test is offered and open. The check that every type renders on GitHub waits on the owner's separate yes.
