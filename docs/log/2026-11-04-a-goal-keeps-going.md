# A standing goal keeps going on judgment

#475, thorough tier on the sensitive route, planned and specified by spec-475, led by the headchef. The owner's words came relayed by the lead session.

A goal set under #434's rule still stopped at each decision the rules keep for the owner, so the owner said they would uninstall the pact if it stopped a goal. Two bullets in the Guards' fixed block replace #434's four: a goal is the owner's words that set it, the session decides on judgment what the rules would bring to the owner and logs it, and usage still holds, so the work parks before the line (ADR 0137). The threat model gains "A standing goal decides alone", and "Removals lose local work" gains "outside a goal".

Two earlier drafts were withdrawn on the owner's word: lists of what a goal takes and never takes, and then a long exhaustive one, which the owner called the rigidity they objected to. A probe of Claude Code's `/goal` showed a goal doesn't get past a stop under the old rules, a session can't set one from inside, and any shell can start one in another session; the owner judged the probing enough and found it expensive.

Spec round 1, the spec pair and the security pair, blocked all four ways on a definition that fitted any ask. The owner's own verb "set" closed it, with the log's shape, the Usage line and the threat-model wording tightened. Seven exceptions the round listed were left out.
