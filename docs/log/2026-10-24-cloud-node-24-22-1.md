# The cloud Node pin moves to 24.22.1

**2026-10-24.** #367. Node's October 2026 security release, high severity on the 24.x line, reached the cloud setup's Node pin. ADR 0088 sets a 7-day limit on a security bump; the release is dated 2026-10-20, so the bump was due by 2026-10-27. Tier: standard, planned and built on Opus at medium. The owner took no sensitive route and no security pair, relayed by the lead session.

## What was built

- **`CLOUD_PINS`** in `cloud-sessions/gen.mjs`: `NODE_VERSION` 24.22.1, with its archive and `bin/node` hashes. The mise pins stay as they were.
- **The cloud copies,** `cloud-setup.sh` and `cloud-setup-wrapper.sh`, regenerated: in each, the three pin lines and the marker's hash change, and nothing else.
- **Tests: +0 −0.** Run after the pin edit and before regenerating, four cloud-copy tests failed, among them "the committed outputs equal what the generator builds"; after regenerating, all passed.

## The pin bump, by ADR 0088

Run in a throwaway `ubuntu:24.04` container, with `gpgv` from Ubuntu's archive and only a scratch copy of the committed keyring mounted, read-only. The copy's SHA-256 matched the one `cloud-sessions/keys/README.md` records.

- **The signature:** `SHASUMS256.txt.sig` for v24.22.1, checked with `gpgv` against `cloud-sessions/keys/node-release-keys.kbx`: a good signature from `5BE8A3F6C8A5C01D106C0AD820B1A390B168D356`. That key is in the committed keyring and in the primary releaser keys of nodejs/node's README at commit `91c4436`. It is not the key that signed 24.22.0, which ADR 0088's key table names; no key changed. A copy of `SHASUMS256.txt` with one byte changed was refused.
- **The archive:** `node-v24.22.1-linux-x64.tar.gz` hashes to `eb6728e7…6002d7c`, as its line in the checked file says.
- **`bin/node`:** unpacked, it hashes to `e32e2d16…7cfafb` and prints `v24.22.1`.

## The test driver

`cloud-sessions/test-driver.sh` ran the regenerated setup in a throwaway `ubuntu:24.04` container, with only its scratch folder mounted, read-only. The setup ran token-free and anonymous.

- **Both passes** printed `ok: node, npm and npx run Node 24.22.1` and the marker `pact cloud copy ed0e9014eac1`, with no `node:` reason. The wrappers ran Node `v24.22.1`, npm and npx `11.19.1`.
- **The hand checks:** a wrong mise, archive or binary pin each printed its mismatch `WARN` and `INCOMPLETE (… node: hash)`. A missing mise release gave `node: download`, `paranoid` off gave `node: config`, and a `uname` stub printing `aarch64` gave `node: arch`.
- **The Node block alone** took 9 s from nothing installed. An untrusted `mise.toml` asking for Node 22 was refused as untrusted, and the wrapper still printed `v24.22.1`. `mise exec node@22` printed `v22.23.4`.
