# The secret and personal-data rules removed

#441, thorough tier on the sensitive route, planned and specified by plan-441, built by build-441, led by the headchef. The owner decided the removal ("nope I'm done with them, nuke them please"); the proceed on revision 4 was the lead's own pick under level 3 (decision 398), not the owner's words.

The pact no longer makes Claude treat a secret or a personal detail in its own text specially (ADR 0126). "Secrets" leaves the sensitive-work default, the security-finding definition loses its exposure clause, the read before posting checks a post against the rest of Posting, the lens files and their contracts drop their own secret rules, and `/scriptorium` no longer reads builder files or presets for keys or names. The poster drops its token-shape, URL-password and email refusals and keeps two: a live environment secret's value, matched exactly (decision 388), and hidden characters. The spec pair and the security pair read two Design rounds; round 2 was declared final.

The build cut the poster's scan rows for the three refusals and kept its normalisation rows, planting the token shape as an environment secret's value, so the kept refusal is still seen reading through entities, comments, escapes and split forms. It added one case that a token shape, a URL password and an email address post, on a new post and on an edit. The threat model's places that named a removed control are reworded, and R3, R13 and R34 move on its risk chart. This repo's own rules on secrets go to a separate issue, filed before merge.

The security pair read the local commit before the push and returned blocking on the removal's own cost: the owner's credential or a personal detail posted to a public tracker, and a reviewed product's secrets in a lens report. The owner, shown the risk to their GitHub account, accepted it as planned ("a", decision 418, relayed by the lead), and R64 to R68 record the classes in the threat model. The owner declined keeping the token-shape refusal as a backstop, over false positives. The second read found nothing new and high, so the branch was pushed; integrity-lens then had the cut fold-and-fence scan test restored on the kept refusals. A final round on the two-commit head, declared final, found nothing new and high; the owner confirmed R64 to R68 and the later threat-model edits (decision 451), and the lead kept the build's test picks (decision 446). Two notes stay in the record, unfiled: a threat-model line names an install warning the installer never printed, already so at the base; and no edit test plants a hidden character.
