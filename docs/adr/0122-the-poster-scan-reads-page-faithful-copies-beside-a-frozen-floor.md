# The poster's scan reads page-faithful copies beside a frozen floor

The poster's content scan, its table check's withheld read and its edit checks now read one set of normalised copies of each text (#394). Before, they read two copies built by a decoder with a short list of named references, so a known-shape secret split by a reference outside that list stayed split in every copy while GitHub's page showed it whole.

## The copies

- **The floor,** two copies built exactly as before #394: the old list (`NAMED`), numbers of at most seven decimal or six hex digits, tags and comments removed every round, one copy without HTML comments and one with their contents kept. It is frozen; nothing is added to its list. It exists so that no form refused before #394 passes now: some of its names fold to an ASCII look-alike the HTML5 table doesn't give (`&dash;` is U+2010 there and `-` here), and its repeated removals catch forms the other copies read as the page does.
- **The page copy:** block-quote markers stripped from each line, as the page strips them before it reads a tag carried onto the next line; then the source's own raw HTML removed once, in one left-to-right scan of each block between blank lines, by the GFM spec's section 6.10 grammar (open tags with any quoted attribute value and ASCII spacing, closing tags, comments, processing instructions, declarations and CDATA sections), keeping backslash escapes and code spans as written. A processing instruction or CDATA section is recognised by its closer, as the grammar does, but removed only up to its first `>`, where the page's HTML parser ends it, and the scan goes on from there. A tag named in section 6.11's filter (title, textarea, style, xmp, iframe, noembed, noframes, script, plaintext, in any case) stays, since GitHub escapes its `<` and the page shows the rest as text. Then, until nothing changes, escapes removed, references decoded as the page decodes them, invisible and control characters stripped, and NFKC applied. It never removes a tag twice, so text that decoding makes tag-shaped stays, as the page shows it.
- **The bare copy:** the same decoding and stripping with nothing removed, for a tag the page shows as text where the page copy reads the source otherwise, such as inside a `~~~` fence.
- **The wide copy:** the page copy's pattern as the first build of #394 had it, frozen: any Unicode spacing in a tag, no tag filter, read over the whole text. Inside an HTML block the page's HTML parser reads a tag the inline grammar rejects, such as one with a no-break space before `=`; this copy reads it, and as one more copy it can only add refusals.
- **The mark fold,** for the content scan only: the page copy with `*`, backticks, `~` and link syntax dropped and `_` kept, since several secret shapes hold `_` and CommonMark never reads it as emphasis inside a word. The table check and the edit checks apply their own folds, which drop `_` too, to every copy.

## Decoding

The page copy and the bare copy decode every name of the HTML5 named character reference table with its semicolon (2,125 names), the 106 legacy names that need none by longest prefix, and numeric references of any length, with or without the semicolon. The tables sit inside `claude/tools/poster.mjs`, since the install ships only `claude/tools/<name>.mjs` for a tool, as plain-ASCII strings a test pins by count and SHA-256. Both come from Python's standard library (`html.entities.html5`, the WHATWG table, which the HTML standard says will not change). These commands, run with Python 3.13 or later, print the two digests; dropping the `hashlib` wrapper prints each string:

```text
python -I -c "import html.entities as e,hashlib;print(hashlib.sha256(','.join(n+':'+'+'.join('%x'%ord(c) for c in v) for n,v in sorted((k[:-1],v) for k,v in e.html5.items() if k.endswith(';'))).encode()).hexdigest())"
python -I -c "import html.entities as e,hashlib;print(hashlib.sha256(','.join(sorted(k for k in e.html5 if not k.endswith(';'))).encode()).hexdigest())"
```

## Why

- **The class, not the list.** The short list was a denylist; every review that read it found another name it missed. The whole table ends that.
- **Held to GitHub's page.** Each form the copies close was probed through GitHub's renderer in `gfm` mode, the mode comments use, with harmless strings: a named zero-width space decodes; zero-padded numeric references, with or without their semicolon, and semicolon-less legacy names decode inside an HTML block; a quoted attribute value may hold `>`; processing instructions, declarations and CDATA sections are hidden; a tag the grammar rejects shows as text; an escaped or code-span tag shows as text. Plain `markdown` mode differs on two of these, so the probes that decided the design were run again in `gfm` mode.
- **Never less.** Each new copy is a reading of the page; the floor keeps every reading of before. A test row only the floor catches (C3, C4, C11) fails if the floor drifts, and each other copy and rule has a row only it catches.
- **Fail closed.** The copies decode, strip and keep more than the page sometimes does, so text the page shows split can be refused; rewording is the fix. Control characters are stripped though GitHub's comments show C0 and C1 controls as U+FFFD and keep form feed as whitespace, and its plain `markdown` mode drops C0 controls: stripping only adds refusals.

## What was weighed

- **Decoding the whole table inside today's pipeline** (spec revision 1). Not taken: decoding and stripping more before the repeated tag removal made new tag shapes that the removal then ate, so some forms caught before would pass (adversarial-lens and data-lens, Design round 1).
- **A separate data file for the table.** Not taken: the install ships one file per tool, and the table is frozen.
- **Dismissing the semicolon-less legacy names** (q7 on #394). Taken in Design on a `markdown`-mode probe, reversed in the build on the `gfm`-mode one (q11).
- **The windows-1252 remap of `&#128;` to `&#159;`.** Not done: GitHub shows U+FFFD there.
- **A markdown parser.** Not taken: the poster has no dependencies. Two tricks at once that no single copy reads together, look-alike letters and other renderers are accepted under R13, on the owner's own word (2026-10-26).
- **Fixing every parser difference by hand.** The security pair's follow-up read of the first build found three more: a processing instruction or CDATA section that the page ends at its first `>`, a tag carried onto the next line of a block quote, and a tag with a no-break space before `=` in an HTML block. Those three are fixed, each with a row only its fix catches. The class, a raw-HTML or markdown structure the page copy reads differently from GitHub's page, is accepted under R13 on the owner's own word (q13, 2026-10-27), and a further difference falls under it. Scanning what GitHub renders in place of modelling its parsers is the follow-up, #429.
- **A linear scanner for the page copy.** The patterns' comment, processing-instruction, declaration and CDATA branches scan from each unclosed opener to the end of a block, and in the wide copy to the end of the text, so a body of 65,536 characters of unclosed openers takes time that grows with the square of its length. Measured on the owner's host, worst of three runs per reader (`scan`, `tableCheck`, `hasDecision`, `isRecord`): at most 655 ms, for unclosed processing instructions, against 293 ms at the first build and 16 ms before #394; C15's fragments take at most 13 ms. All are under the one-second bound, and nothing is sent while it runs. Accepted as R62 on the owner's standing word, relayed by the lead (q12).
