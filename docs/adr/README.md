# Decision records

One line per ADR: what it decided, and when to read it. Open the file for the reasoning.

- [0001](0001-plain-agent-names.md) — **Plain agent names.** Agents are named for their job. Read when naming or renaming an agent.
- [0002](0002-tool-allowlists.md) — **Tool allowlists.** Agents list the tools they may use, not the ones they may not. Read when changing an agent's `tools:` line.
- [0003](0003-missing-tool-is-reported.md) — **A missing tool is reported.** An agent stops and names the tool; it never rebuilds it through the shell. Read when an agent lacks a tool.
- [0004](0004-gate-on-after-dispatch-needs.md) — **Gate on after-dispatch needs.** Builder hand-offs were gated on needs that arise after dispatch (builders since retired by 0010). Read for the history of move 3.
- [0005](0005-status-line-and-verbatim-relay.md) — **Status line and verbatim relay.** Builders opened with a STATUS line; BLOCKED was relayed word for word. Read for the history of verbatim relay.
- [0006](0006-root-agents-md.md) — **Root AGENTS.md.** This repo's rules live in AGENTS.md; CLAUDE.md only imports it. Read before adding a repo rule.
- [0007](0007-only-decisions-are-committed.md) — **Only decisions are committed.** Plans and reviews live on the issue; the tree keeps ADRs and logs. Read when deciding where a record goes.
- [0008](0008-throwaway-after-two-paper-rounds.md) — **Throwaway after two paper rounds.** Two review rounds without READY open the option of a throwaway build. Read when a plan review stalls.
- [0009](0009-hand-over-user-only-skills.md) — **Hand over user-only skills.** The model ends its turn with a `▶ Your move` line instead of running the skill. Read when a move reaches a user-only skill.
- [0010](0010-build-in-the-main-session-with-process-tiers.md) — **Main-session builds and process tiers.** Builds run in a watched main session; work gets a tier up front. Read for why builder agents retired and how tiers began.
- [0011](0011-one-model-per-session.md) — **One model per session.** Sessions split at phase boundaries and never switch model. Read when planning sessions or models.
- [0012](0012-reports-for-two-readers.md) — **Reports for two readers.** Reading agents write For the owner, then For the session. Read when writing or changing a reviewer's report format.
- [0013](0013-effort-follows-the-tier.md) — **Effort follows the tier.** One effort value per tier and phase, copied by triage. Read when setting a session's effort.
- [0014](0014-evidence-in-proportion-to-the-cost-of-being-wrong.md) — **Evidence in proportion.** A planted probe only on the security floor; proof by use otherwise. Read before testing a rule or agent change.
- [0015](0015-practice-runs-in-an-isolated-container.md) — **Practice runs in a container.** Real practice runs happen in a sandbox that never holds the checkout. Read before running a practice case or probe.
- [0016](0016-each-lens-opens-with-a-red-step.md) — **Each lens opens with a red step.** A lens writes how each claim could be wrong before it looks at evidence. Read when writing or changing a lens.
- [0017](0017-lens-files-ship-unsealed.md) — **Lens files ship unsealed.** The QA-pair lenses are plain files in `claude/agents/`. Read when changing where a lens lives.
- [0018](0018-fix-path-stands-in-for-the-plan-review.md) — **Fix path for case fixes.** A security-set case fix that keeps its expected result goes through #35's fix path, not a spec change. Read when a security-set case fails.
- [0019](0019-recommendations-are-auto-taken-with-a-trail.md) — **Recommendations are auto-taken, with a trail.** A session acts on its recommendation for report findings and logs an `auto` row. Read when changing "Help me decide".
- [0020](0020-the-apply-guard-catches-what-text-can.md) — **The apply guard catches what text can.** The `-Apply` ask rules catch the script name followed by a dash or a splat; the rest are named misses. Superseded by 0042.
- [0021](0021-executability-is-judged-at-spec-time.md) — **Executability is judged at spec time.** `executability-lens` checks the spec names its target environment, a clean build and lint, and an end-to-end run; it runs nothing. Read before changing what the spec pair checks.
- [0022](0022-a-sign-case-scores-the-sign-in-its-own-finding.md) — **A sign case scores the sign in its own finding.** The sign must open the bullet of a `high` finding on a planted section; the rest of the plant is not policed. Read before changing a sign case or `bulletOn`.
- [0023](0023-a-payload-is-judged-by-running-it.md) — **A payload is judged by running it.** A case that forbids a working payload runs every candidate string in the plant's query in Node's built-in SQLite; the accepted scope is named. Read before changing `sqlPayload` or a payload case.
- [0024](0024-the-data-lens-checks-encryption-and-approved-flows.md) — **The data lens checks encryption and approved flows.** `data-lens` asks whether data is encrypted at rest and in transit and whether each outgoing flow is approved, and carries ASVS V11 and V12. Read before changing what `data-lens` checks.
- [0025](0025-a-configuration-sets-only-non-security-lenses.md) — **A configuration sets only non-security lenses.** The `agents` key may set `integrity-lens`'s model and effort; every security-set agent stays locked. Superseded by 0027.
- [0026](0026-the-config-builder-is-rendered-from-a-builder-file.md) — **The config builder is rendered from a builder file.** The pact's half comes from the clone, the person's half from their builder file, written by the `scriptorium` skill. Read before changing the builder or its skill.
- [0027](0027-every-pact-lens-is-configurable-with-opinionated-defaults.md) — **Every pact lens is configurable, with opinionated defaults.** The `agents` key may set any pact lens's model and effort; each file's own values are its default, `scout` stays sealed, and a security-set lens's override is marked "override, not security-tested". Read before changing the configurable list or how security-set lenses are classified.
- [0028](0028-the-moves-name-practices-a-person-binds-their-own-skills.md) — **The moves name practices; a person binds their own skills.** The default rules name no skill; a block binds one as a code span (agent) or a command (owner's). Read when changing how a move names a step or a skill.
- [0029](0029-the-gate-suite-runs-capped-on-the-current-node-lts.md) — **The gate suite runs capped, on the current Node LTS.** The documented suite commands carry `--test-concurrency=4` and AGENTS.md names the Node LTS and Volta; a bare `node --test` is uncapped. Read before changing how the suite is run.
- [0030](0030-the-gate-suite-runs-through-one-runner-in-named-tiers.md) — **The gate suite runs through one runner, in named tiers.** `run.mjs full` is the full suite and `fast` leaves out the install tier, found from imports; the runner always caps at four, fails closed, and writes scrubbed records for posting; it and the copy list sit on the probe floor. Read before changing how the suite is run or picked.
- [0031](0031-gate-bad-cases-are-table-rows-and-no-case-is-lost.md) — **Gate bad cases are table rows, and no case is lost.** A bad case is a row in its module's table, proved to fail by its plant; the T1 baseline is committed, and `baseline-compare.mjs` checks every move-4 full run against it and the map of moves. Read before adding a bad case, or moving or renaming a test.
- [0032](0032-gate-modules-split-into-a-core-and-a-thin-wrapper.md) — **Gate modules split into a core and a thin wrapper.** `gate/<m>-core.mjs` exports `check(argv)` and does nothing when imported; `gate/<m>.mjs` is four statements that run it, and the install runs it unchanged. An in-process caller must keep five controls the install gives a check. Read before changing a gate module, calling a check in-process, or planting into a module's text in a test.
- [0033](0033-one-layer-per-test-file.md) — **One layer per test file.** A gate test file holds install cases or cases that never install; the install harness fails a test in an install-tier file that neither installs nor skips, and a test that only reads the install script reads it through a helper. Read before adding a test to an install file, or reading the install script in a test.
- [0034](0034-test-helpers-split-by-what-they-touch.md) — **Test helpers split by what they touch.** `text`, `tree`, `gate-files`, `payload`, `gate-run` and the install harness replace `helpers.mjs`; only `payload.mjs` reads the agents, so an agent-file change picks only the tests that read them; no helper does I/O at import, and `makeRepo` doesn't route. Read before adding a test helper or importing one.
- [0035](0035-publish-with-the-history-as-it-is.md) — **Publish with the history as it is.** The repo and its tracker go public unrewritten; the tree is cleaned and guarded, every published surface is scanned first, and the README serves any reader. Read before changing what history or tracker text may hold, or who the README is for.
- [0036](0036-only-the-owners-tracker-text-counts.md) — **Only the owner's tracker text counts; outsiders' code never runs.** The gated `tracker-authors` clause: only the login `gh api user` returns can decide, read from JSON author fields, with its own last edit and label; everything else is data; only the owner's own same-repo PRs are insiders' code, and outsiders' code runs only on the owner's typed OK in a bare container. Read before acting on tracker text, relaying an owner decision, or running a PR's code.
- [0038](0038-the-cloud-copy-is-generated-through-the-render-and-seam-a.md) — **The cloud copy is generated through the render and seam A, and test-checked.** `cloud-sessions/gen.mjs` builds `CLAUDE.cloud.md` and both setup scripts from seam A's copy set plus two pinned cloud edits; the setup checks every file's hash and prints a marker; a `fast` test fails when an output is stale; changes stay on the security route. Read before changing `cloud-sessions/` or the cloud setup.
- [0039](0039-the-install-is-a-node-bootstrap-and-a-staged-runner.md) — **The install is a Node bootstrap and a staged runner, with the checks in-process.** `node gate/install.mjs` replaced `install.ps1`: a small bootstrap stages HEAD's files and starts the runner from the stage; every check runs in-process with ADR 0032's controls; decisions are pure functions with rule ids; every apply is bound to its dry run's commit; the floor is Node 24. Read before changing the install, its command line or its known limits.
- [0040](0040-a-link-test-replaces-the-reparse-attribute-test.md) — **A link test replaces the reparse-attribute test.** Each segment below the root is tested with `lstat` and its real path, failing closed; a reparse point that doesn't redirect now passes. Read before changing how the install refuses a link.
- [0041](0041-a-required-ci-check-guards-main.md) — **A required CI check guards main.** `gate.yml` runs the install's dry run and the `fast` tier on every pull request, locked down; the ruleset requires its `gate` check from GitHub Actions, up to date, with no bypass. Read before changing the workflow or the ruleset.
- [0042](0042-the-apply-guard-asks-on-any-command-naming-the-install.md) — **The apply guard asks on any command that names the install.** Twelve ask rules, on the script, its runner, the old installer, the record and the ruleset; the habit risk and the misses are accepted; supersedes 0020. Read before changing the ask rules or the install-go-ahead clause.
